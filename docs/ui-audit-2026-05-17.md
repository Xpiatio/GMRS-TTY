# GMRS-TTY UI/UX Visual Audit — 2026-05-17

This document is the **Phase A deliverable** of a two-phase UI improvement effort. Phase B (dockable panel refactor + the P0/P1 fixes below) is gated on user sign-off here. The plan it implements lives at `/home/benjamin/.claude/plans/lets-review-the-ui-serialized-mist.md`.

---

## 1. Scope & method

**Reviewed:**
- `gmrs_tty/ui/main_window.py` (~1620 lines) — the entire main window
- `gmrs_tty/ui/theme.py` (180 lines) — both light and dark palettes
- `gmrs_tty/ui/chat_display.py` (224 lines) — the chat surface and its pill formatting
- `gmrs_tty/ui/flow_layout.py` — confirmed reusable for wrap behavior
- `gmrs_tty/ui/spectrogram_widget.py` — only touched to confirm reparenting will work

**Deferred to a separate audit (not in this pass):**
- `gmrs_tty/ui/config_dialog.py`
- `gmrs_tty/ui/contacts_dialog.py`
- `gmrs_tty/ui/quick_messages_dialog.py` + `AddContactDialog`
- Status-bar messages and toast-style chat-line notifications

**Method:** static read of source, cross-referenced against both palettes. No runtime profiling. Each finding has a `file:line` anchor that resolves in the current `main` branch.

**Conventions:**
- **P0** — blocks shipping a quality bar; either a WCAG-adjacent contrast/affordance failure or a cross-platform rendering risk.
- **P1** — visible polish; the UI works but reads as inconsistent or under-considered.
- **P2** — nice-to-have; mostly affects power users or edge states.

## 2. Executive summary

The app's information architecture is sound — sections appear in a sensible top-down reading order, and accessibility coverage (accessible names, descriptions, mnemonics, font-scale resilience) is unusually thorough for a hobby-scale codebase. The weak spots are **consistency** (mixed component vocabulary, ad-hoc spacing/padding, no typography scale, semantic-color overload in dark mode) and **responsive behavior** (the TX input row crowds at the 720px minimum width). Total: **16 findings** — 3 P0, 8 P1, 5 P2.

**Top 3 to fix first:**

1. **F-001** — Dark `pill_border` and `warn` collapse to the same `#FBBF24`; pending pills become visually indistinguishable from warn-state text.
2. **F-002** — Emoji-presentation glyphs (`⚙️`, `👤`, `🌙`/`☀️`) render inconsistently across platforms and break with `setFont(size+4)` because emoji fonts rarely respect Qt point sizing.
3. **F-003** — Quick-Messages icon is a bold letter `"Q"` while neighbors are emoji — pick one vocabulary or the icon strip reads as broken.

## 3. Cross-cutting findings

### 3.1 Spacing tokens

Padding and inter-widget spacing values are sprinkled throughout the source with no shared definition. Documented variants found:

| Value | Used at | Purpose |
|------|---------|---------|
| `5px` padding | `main_window.py:351` (chat_display) | Inner padding |
| `10px` padding | `theme.py:163` (header) | Inner padding |
| `4px 10px` padding | `theme.py:178` (pill button) | Inner padding |
| `spacing=5` | `main_window.py:382, 385, 420` | FlowLayout / HBoxLayout inter-widget |
| Qt default (~6 or 9) | `main_window.py:174` main QVBoxLayout | Section-to-section |

See **F-004** for the recommendation.

### 3.2 Typography scale

Only the header label gets a custom QFont (`main_window.py:317-320` — bold, +2pt). Every other widget — message input, chat display, pending pills, quick messages, buttons — inherits the OS default font with no scale relationship. The icon strip bumps font size by +4pt (`main_window.py:220`) but this is applied to emoji glyphs and a bold letter, not to a typography role. See **F-005**.

### 3.3 Component vocabulary

The window mixes:
- **`QPushButton`** for: Clear chat, Listen, Transmit, This is, Dismiss all, pending pills, quick messages
- **`QToolButton`** (`autoRaise=True`) for: theme toggle, Q (quick messages), 👤 (contacts), ⚙️ (config)
- **`QRadioButton`** for: GMRS / FRS
- **`QLabel`** for: header, online indicator

The icon strip's four `QToolButton`s are visually identical except that three are emoji and one is a bold letter — see **F-003**. The pending-pill `QPushButton`s look like badges, not buttons — see **F-007**.

### 3.4 Color semantics

The amber/warm-brown family is used for **three** semantically distinct roles:

| Role | Light hex | Dark hex |
|------|-----------|----------|
| `warn` (warning text/icons) | `#92400E` | `#FBBF24` |
| `pill_border` (pending pill outline) | `#A16207` | **`#FBBF24`** |
| `pill_bg` (pending pill background) | `#FEF3C7` | `#78350F` |
| `online_offline` (network status) | `#92400E` | `#FBBF24` |

In dark mode, `warn`, `pill_border`, and `online_offline` all resolve to **exactly the same hex** — `#FBBF24`. A user looking at a warn-state chat line, a pending-station pill border, and an offline indicator sees three identical amber strokes. See **F-001**.

### 3.5 Focus visibility

`QToolButton(autoRaise=True)` has no painted resting state — that's the point. But it also means Qt's default focus rect is often invisible on the icon strip (`main_window.py:226-292`), so a keyboard-only user can lose track of which icon is focused. There is no `:focus` stylesheet defined anywhere in the app. See **F-014**.

## 4. Section-by-section findings

### 4.1 Service-mode row (`main_window.py:180-313`)

This single horizontal row carries seven UI elements: `Service:` label, GMRS radio, FRS radio, stretch, 🌙 theme toggle, Q quick-messages, 👤 contacts, ⚙️ config, ● Online indicator. At the 720px window minimum (`main_window.py:540`), the radios and the icon strip pack against each other with no breathing room, and on Linux without a color emoji font the icons collapse to monochrome boxes (see **F-002**).

The online indicator is a `QLabel` placed *after* the action icons — see **F-010**: in some Qt styles labels can receive Tab focus depending on `focusPolicy`, which would put a non-interactive status display in the keyboard traversal.

### 4.2 Header label (`main_window.py:315-327`)

The header is a centered, bold, +2pt QLabel with a 10px-padded background. In light mode the background is `#F0F0F0` against a `#FFFFFF` window background (`theme.py:62`) — only ~8% luminance difference, so it reads as a faint smudge rather than a distinct card. See **F-009**.

### 4.3 Chat toolbar (`main_window.py:329-346`)

A full horizontal row spent on one right-aligned button ("Clear chat"). This burns a layout row's vertical budget for a single low-frequency action. In the Phase-B docking layout this becomes an inline element of the central widget wrapper rather than its own dock — but even in today's layout it could move into the View menu or onto the input row.

### 4.4 Chat display (`main_window.py:348-357`, `chat_display.py`)

The "pill" formatting in `chat_display.py:141-153` uses **underline + underline-color** as a border-radius workaround (because `QTextEdit`'s HTML subset rejects border-radius — comment at `chat_display.py:147-149`). Meanwhile, the *pending-station* pills (`theme.py:175-180`) use a real border and real border-radius. Two things called "pills" in the same UI have **different visual treatments** — one is a colored block with an underline, the other is a rounded border with internal padding. See **F-016**.

### 4.5 Spectrometer (`main_window.py:359-374`)

Mostly clean. Hidden by default; the only audit note is that when both the spectrometer and quick-messages strip are hidden, the QVBoxLayout collapses with no transitional spacing — verify no double-gap. See **F-013**.

### 4.6 Pending stations bar (`main_window.py:376-411`)

Two issues:
- Pills *look like* badges (rounded, padded, bordered) but they're `QPushButton`s with click-to-open-add-dialog behavior. There is no `:hover` state defined, no `cursor=PointingHandCursor`, and no visual rest/hover/pressed differentiation. See **F-007**.
- The right-click "Dismiss" menu (`main_window.py:1510-1521`) is a bare `QMenu` with one action, no icon, no separator. See **F-015**.

### 4.7 Quick messages strip (`main_window.py:413-430`)

The strip is shown only when the operator has saved presets. No visible affordance to *add* a preset from the strip itself; the entry point is via the "Q" icon or `Settings → Quick Messages`. Consider an inline `+` button on the strip when it's visible.

### 4.8 Input row (`main_window.py:432-489`)

Five widgets packed into one horizontal layout: Listen button | 80px input meter | 120px-min target dropdown | message line edit | Transmit button. At the 720px minimum width, the line edit collapses to <200px after accounting for the four fixed-width siblings. See **F-006**.

The Transmit button has the same visual weight as Listen — but Transmit is the **primary action** of the entire window. Consider primary-action styling (filled background using `palette().tx`) so the eye is drawn to it.

### 4.9 ID button row (`main_window.py:491-499`)

"This is" sits alone in a right-aligned row beneath Transmit. Visually it reads as a stranded button rather than part of a station-control cluster. See **F-008**.

## 5. Theme-specific findings

### 5.1 Light mode

- Header card has weak contrast against window — see **F-009**.
- `online_offline` (#92400E) on `header_bg` (#F0F0F0) — fine, ~7.2:1.
- `pill_bg` (#FEF3C7) with `pill_text` (#78350F) — ~7.9:1, comfortably above AA.

### 5.2 Dark mode

- Three amber roles collapse to identical hex — see **F-001**.
- `placeholderText` palette role is set to `window_text` (`theme.py:150`) — placeholders render at the same color as typed text, so the operator can't tell at a glance whether the input is empty. See **F-012**.

### 5.3 Theme transition

`apply_theme` walks `chat_display.restyle_for_theme()` which uses an underline-vs-background heuristic to distinguish text spans from pills (`chat_display.py:155-201`). Robust enough today, but the heuristic is fragile if future spans gain a non-pill background. Not a current bug.

## 7. Accessibility audit

### 7.1 Color contrast (Web AIM ratio against window background)

| Pair | Light | Dark |
|------|-------|------|
| `rx` text on `window_bg` | `#15803D / #FFFFFF` = 5.49:1 ✓ | `#4ADE80 / #1F2937` = 8.16:1 ✓ |
| `tx` text on `window_bg` | `#1D4ED8 / #FFFFFF` = 7.66:1 ✓ | `#60A5FA / #1F2937` = 6.20:1 ✓ |
| `error` text on `window_bg` | `#B91C1C / #FFFFFF` = 5.93:1 ✓ | `#F87171 / #1F2937` = 6.34:1 ✓ |
| `warn` text on `window_bg` | `#92400E / #FFFFFF` = 7.21:1 ✓ | `#FBBF24 / #1F2937` = 9.18:1 ✓ |
| Pill text on pill bg | `#78350F / #FEF3C7` = 7.93:1 ✓ | `#FDE68A / #78350F` = 6.21:1 ✓ |
| Header text on header bg | `#000 / #F0F0F0` = 18.86:1 ✓ | `#F9FAFB / #374151` = 11.36:1 ✓ |

All pairs meet WCAG AA (≥4.5:1 for normal text). Several clear AAA (≥7:1).

### 7.2 Keyboard-only walkthrough (proposed test path)

Open the app, press Tab repeatedly without using the mouse. Verify each of:
- Service radios receive focus and respond to arrow keys.
- Theme / Q / Contacts / Config icon buttons receive focus (and have a visible focus ring — currently they don't; see **F-014**).
- Online indicator is **skipped** (it's status, not interactive); see **F-010**.
- Chat display receives focus but tab moves past it (it's read-only, scrolling via arrow keys).
- Listen → target dropdown → message input → Transmit → This is, in that order (matches the explicit `setTabOrder` chain at `main_window.py:503-506`).
- Mnemonics: `Alt+G`, `Alt+F`, `Alt+L`, `Alt+T`, `Alt+I`, `Alt+1..9` all activate their targets.

### 7.3 Screen-reader labels

Every interactive widget reviewed has `setAccessibleName` + `setAccessibleDescription` set. The header, online indicator, and audio level meter also have accessible metadata. Coverage is excellent — no missing labels found.

### 7.4 Font scaling

No hardcoded pixel font sizes in widgets — `QFont(self.font()).setPointSize(self.font().pointSize() + N)` is the consistent pattern. OS font scale carries through. The header card uses +2pt (`main_window.py:319`) and the icon strip uses +4pt (`main_window.py:220`).
